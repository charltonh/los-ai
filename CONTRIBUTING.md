# Contributing to LOS

Thank you for your interest in contributing! LOS is developed in the open, and
contributions from the community — code, documentation, bug reports, ideas —
are what make it useful.

## How to contribute

1. **Issues first.** Open an issue describing the bug or proposal before
   sending large changes.
2. **Branch and commit.** Keep commits focused and described clearly.
3. **Tests.** Include tests for new behavior where the project supports them.
4. **Pull request.** Reference the issue, describe what changed and why.

## Style and conduct

- Be constructive; assume good faith; don't be a jerk.
- Follow the existing code style and structure of the module you touch.
- Keep public API changes documented in the README.
